# Technology Watch 引き継ぎ資料

作成日: 2026-09-21

## 1. プロジェクトの目的

一次情報（公的機関などの公式サイト）に基づいて記事を作る仕組みを作る。流れは次の 4 段で、各段の判断基準は**編集方針**として定める。

1. 一次情報を集める
2. 編集方針に沿って取捨選択する
3. 編集方針で定めた観点で情報を構造化する
4. 構造化された情報から、編集方針に沿って最終的な記事を生成する

編集方針はレイヤー別に定義する。

| レイヤー | 編集方針が決めること |
|---|---|
| 取捨選択 | どの情報源・どの種類の情報を採り、何を捨てるか |
| 構造化 | どの観点（項目）で情報を整理するか |
| 記事生成 | 記事の形式、文体、長さ、図表の扱い、品質基準 |

## 2. 方法

| 段階 | 内容 | 保存するもの |
|---|---|---|
| 2.1 更新リストの取得 | 一次情報源（サイト）から更新情報のリストを取得する（HTML の一覧ページ、または RSS） | 更新リスト |
| 2.2 個別情報の取得 | リストから個別の HTML / PDF を取得する | オリジナル（原本）と Markdown の両方 |
| 2.3 素材情報の抽出 | 個別情報の Markdown から、編集方針に沿って構造を抽出する。足りない知識は Wikipedia などで補う | 素材情報を JSON で保存（柔軟性と構造化を両立させるため） |
| 2.4 記事の生成 | JSON の素材情報から、編集方針に沿って記事を生成する。必要に応じて画像を引用、または生成する | 記事 |
| 2.5 公開 | 記事として公開する | 公開済み記事 |

## 3. 言語

| 方向 | 対応言語 |
|---|---|
| 入力（一次情報） | 日本語、英語、ドイツ語、フランス語、中国語の 5 言語 |
| 出力（記事） | 日本語、英語、ドイツ語、フランス語、中国語、韓国語の 6 言語 |

出力を 16〜24 言語から 6 言語に改めた（2026-09-23）。技術ジャーナリズムが
成り立つ言語はそう多くない、という判断による。世界の研究開発費（2022年、
購買力平価、NSF NCSES）は上位 8 か国・地域で 82% を占め、米国 30%、中国
27%、日本 2,008 億ドル、ドイツ 1,749 億ドル、韓国 1,390 億ドル、英国
1,026 億ドル、フランス 852 億ドル、台湾 640 億ドル。台湾は中国語、英国は
英語に含まれるので、日英独仏中の 5 言語で約 72%、韓国語を足して約 77%
になる。韓国はフランスの 1.6 倍の研究開発費を持ち、この媒体が追う半導体・
電池・ディスプレイの中心にいる。ロシアは上位 8 位に入らず（台湾の 640 億
ドル未満）、言語を足しても 2% に届かないため見送った。

出力言語は研究者ではなく一般読者のために選ぶ。研究者は英語を読むので、
ドイツ語版やフランス語版の読者は一般読者と政策の側である。

律速は翻訳の費用ではなく、**読めない言語の記事は誤りを検出できない**こと。
素材情報は一次情報の言語のまま保つ設計なので、言語はあとから足せる
（2.3 は翻訳せず、2.4 が出力言語ごとに書く）。

## 4. 技術スタック

| 項目 | 方針 |
|---|---|
| Web アプリ | Laravel |
| DB | PostgreSQL |
| ワーカー | Python |
| 実行基盤 | AWS 移行を念頭に Docker で構成し、ワーカーのジョブはキューで管理する |
| クローラー（2.1、2.2） | DOM ツリーに対して決定論的に動く。初回と、レイアウト変更などで動かなくなったときは、エージェントが設定を作り直す |
| 記事生成（2.4） | 品質基準を設定し、エージェントが品質を上げる |
| モデル | Anthropic に限定しない。適した用途では OpenAI の安いモデルも使う |
