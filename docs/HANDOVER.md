# Technology Watch 引き継ぎ資料

作成日: 2026-09-21

## 1. プロジェクトの目的

一次情報（公的機関などの公式サイト）に基づいて記事を作る仕組みを作る。流れは次の 4 段で、各段の判断基準は**編集方針**として定める。

1. 一次情報を集める
2. 編集方針に沿って取捨選択する
3. 編集方針で定めた観点で情報を構造化する
4. 構造化された情報から、編集方針に沿って最終的な記事を生成する

編集方針はレイヤー別に定義する。

| レイヤー | 編集方針が決めること |
|---|---|
| 取捨選択 | どの情報源・どの種類の情報を採り、何を捨てるか |
| 構造化 | どの観点（項目）で情報を整理するか |
| 記事生成 | 記事の形式、文体、長さ、図表の扱い、品質基準 |

## 2. 方法

| 段階 | 内容 | 保存するもの |
|---|---|---|
| 2.1 更新リストの取得 | 一次情報源（サイト）から更新情報のリストを取得する（HTML の一覧ページ、または RSS） | 更新リスト |
| 2.2 個別情報の取得 | リストから個別の HTML / PDF を取得する | オリジナル（原本）と Markdown の両方 |
| 2.3 素材情報の抽出 | 個別情報の Markdown から、編集方針に沿って構造を抽出する。足りない知識は Wikipedia などで補う | 素材情報を JSON で保存（柔軟性と構造化を両立させるため） |
| 2.4 記事の生成 | JSON の素材情報から、編集方針に沿って記事を生成する。必要に応じて画像を引用、または生成する | 記事 |
| 2.5 公開 | 記事として公開する | 公開済み記事 |

## 3. 言語

| 方向 | 対応言語 |
|---|---|
| 入力（一次情報） | 日本語、英語、ドイツ語、フランス語、中国語の 5 言語 |
| 出力（記事） | 一次情報の言語で 1 本書き、日本語・英語・繁体字中国語・簡体字中国語へ翻訳する |

**記事は一次情報の言語で書き、他言語は翻訳する**（2026-09-23）。素材情報から
各言語の記事を別々に生成するのではない。一次情報のニュアンスが翻訳を通して
各国語へ残り、生成を何度も回すより効率がよい。結果として、フランス語の一次
情報は日本語の記事になるが、日本語の一次情報はフランス語にはならない。

**翻訳には一次情報と素材情報を文脈として渡す**。文脈のない翻訳は用語を誤訳
する（LLM を法学修士と訳した市販の AI 翻訳がある）。文脈は用語・固有名詞・
数値を決めるためだけに使い、記事に足したり直したりしない。

出力言語を 16〜24 から絞った理由。技術ジャーナリズムが成り立つ言語はそう多く
ない。世界の研究開発費（2022年、購買力平価、NSF NCSES）は上位 8 か国・地域で
82% を占め、米国 30%、中国 27%、日本 2,008 億ドル、ドイツ 1,749 億ドル、韓国
1,390 億ドル、英国 1,026 億ドル、フランス 852 億ドル、台湾 640 億ドル。台湾は
中国語、英国は英語に含まれる。中国語は簡体字と繁体字を分ける。ロシアは上位 8
位に入らず（台湾の 640 億ドル未満）、足しても 2% に届かない。

出力言語は研究者ではなく一般読者のために選ぶ。研究者は英語を読むので、各国語版
の読者は一般読者と政策の側である。律速は翻訳の費用ではなく、**読めない言語の
記事は誤りを検出できない**こと。素材情報は一次情報の言語のまま保つので、言語は
あとから足せる。

## 4. 技術スタック

| 項目 | 方針 |
|---|---|
| Web アプリ | Laravel |
| DB | PostgreSQL |
| ワーカー | Python |
| 実行基盤 | AWS 移行を念頭に Docker で構成し、ワーカーのジョブはキューで管理する |
| クローラー（2.1、2.2） | DOM ツリーに対して決定論的に動く。初回と、レイアウト変更などで動かなくなったときは、エージェントが設定を作り直す |
| 記事生成（2.4） | 品質基準を設定し、エージェントが品質を上げる |
| モデル | Anthropic に限定しない。適した用途では OpenAI の安いモデルも使う |
